# R-03: media, editing and interchange qualification

Research date: 2026-11-02. Source inspection is bounded to the paths/functions below. Retrieved upstream tests are evidence of intended cases, not passing Yamakan tests. No new library, binary, decoder, model or renderer was installed or executed. Public source heads are research pins; they do not replace the production versions in the lockfile and media trust manifest.

## Current integration boundaries actually inspected

Baseline `TheHalfMoon/Yamakan@c129a50c9e6bf9657f404c919c3cf6dbb8273697` remains selected. `core/render/plan.ts::compilePlan` feeds `core/render.ts::renderPlan` and segmented export. `core/render/preview.ts::preview` uses the same compiled plan, caption/font/color inputs and renderer identity. Its queue is serialized, identical requests share work while waiters remain, admission is bounded, and staging is removed on completion/failure. Cache identity includes plan, frame window, renderer version and FFmpeg identity. These mechanisms already exist; SS-009 qualifies their edge cases rather than replacing them.

`core/timeline/snapping.ts::resolveTimelineSnap` already adapts OpenCut Classic at `cf5e79e919144200294fb9fed22a222592a0aeea` to integer flick ticks. `core/audio/loudnorm.ts::measurePassFilter`, `applyPassFilter`, `parseLoudnormJson` already support measured two-pass loudness. `core/interchange/otio.ts::toOtio` and `fromOtio` use bounded JSON proposals, integer flick-rate timing and asset matching; input `target_url` is never fetched. Its same-application metadata round-trip is not evidence that arbitrary NLEs preserve effects/transitions. Title clips are excluded from its clip mapping, so export loss must be disclosed.

Production media remains FFmpeg **7.1.1**, libass **0.17.3**, the r8 DLL closure and exact hashes in `vendor/ffmpeg-win64-r8/BUILD.json`/`SHA256SUMS`; production browser packages remain `mediabunny@1.61.3`, `jassub@2.5.20`, `soundtouchjs@0.3.0`. A later upstream source observation is not proof of behavior in these installed versions. No upgrade is selected by this plan.

## Standards and Windows alternatives

The [WebCodecs specification](https://www.w3.org/TR/webcodecs/) documents asynchronous codec queues, presentation timestamps and explicit media-resource lifetimes. A codec's internal queue saturation is not Yamakan's byte budget. The [WebGPU specification](https://www.w3.org/TR/webgpu/) requires handling absent adapters/device loss and invalidates outstanding work on destruction. These are interface contracts, not repository implementation donors or evidence of faster output on the qualification machine. **DEFER new WebCodecs/WebGPU backend**; use these lifecycle/fallback cases to assess existing browser paths.

[Windows Media Foundation source-reader attributes](https://learn.microsoft.com/en-us/windows/win32/medfound/source-reader-attributes) expose asynchronous callbacks, D3D managers and hardware-transform choices. Hardware availability, codec rights, driver behavior and output parity are not established by setting an attribute. **DEFER native Windows decoder replacement**. A future experiment must retain the FFmpeg fallback, bound surfaces/queues, handle device loss and prove VFR/color/alpha/A-V parity before any architecture change.

## Selected implementation contract

**Selected closure:** current registry → canonical transaction/snapshot → compiled render plan → owned native worker → validated managed artifact. No upstream runtime above is newly imported. Existing donor hashes/licenses stay in `docs/provenance/imports.json`; exact runtime bytes stay in r8 manifests. Newly copied source, even a small helper, would require its own import record, notices, dependency closure and review. Conceptual test cases are not represented as copied code.

**Concrete improvement boundaries:** SS-009 is cache invalidation, cancellation and frame disposal qualification; SS-012 is measured loudness/mix evidence and truthful control state; SS-013 is exact cue timing/bilingual keyboard qualification; SS-014 is snapping/trim/crossfade boundary interaction qualification. Existing passing behavior can close a qualification step with an exact receipt; defects become bounded fixes inside the named boundary. No task authorizes arbitrary DSP, a new timeline store or a renderer rewrite.

**M experiment:** keep algorithm selection conditional on SS-005a measurements. The bounded candidate is reducing redundant decode/scale work across unchanged overlapping segment inputs while preserving per-frame overlay order and reference output. Reject the candidate if it requires unbounded retained frames, a new scheduler or altered segment/animation/loudness semantics. If measurement identifies no safe win, SS-005b records REJECTED/NO-GO rather than manufacturing an optimization. Conditional measured selection is an executable experiment, not unfinished competitor research.

**Acceptance:** exact integer/rational frame boundaries; alpha/transform/LUT/animation controls; decoded audio onset/sync; segment joins; missing/changed assets; wrong project/revision; cancellation before publication; lease expiry; cache pressure; fallback on unsupported browser capability. Use the frozen policy in [10](10_PERFORMANCE_AND_BENCHMARK_PROGRAM.md), retaining every timeout/failure and paired baseline. No new latency or resource promise is derived from source code.

**Rollback/maintenance:** revert one graph/UI/cache delta, bump or restore renderer/cache version consistently, retain original media and reference export, and never migrate canonical data for a rejected experiment. Opus owns integration; renderer, preview and audio changes serialize through one media qualification slot. Upstream drift is a review input, not an automatic upgrade. R-03 remains pending independent review of this bounded qualification.
