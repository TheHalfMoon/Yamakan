## A bounded research unit

For each product, capture the official identity/URL, version or access date, platform, available evidence and whether hands-on access was possible. Review all twenty generative-product dimensions from the directive: journey, workflow, project structure, assets, references, scenes, cinematic controls, timeline, orchestration, automation, agent behavior, history, revisions, export, APIs/SDK/CLI/MCP, prices/resources, limitations, reliability, user value and possible Yamakan advantage. Mark non-applicable dimensions with a reason.

Use primary manuals, API references, release notes and actual public code before community commentary. Do not purchase subscriptions or upload private footage to inspect a product. Unavailable hands-on access is a named limitation. Record exact quotes/sections only where needed to support conclusions; keep large captures local. Pricing is a dated fact, not a spending authorization.

Each important capability must have this row:

| Competitor | Capability | Evidence and date | Why it matters | Yamakan current behavior/gap | Source candidates | REA decision | Yamakan target | Tests |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Named product | Narrow behavior | Label plus source URL/version | Concrete creator problem | Code/receipt inspected | At least two where available | COPY/ADAPT/WRAP/COMBINE/BUILD/DEFER/REJECT | Existing boundary | Positive, negative, media/resource cases |

Explain why the selected source is preferable and whether integration is realistic. A closed backend cannot qualify as a donor. “Yamakan could be better” stays a hypothesis until a matched test exists. Inspect the actual Yamakan path before declaring a gap.

## Discovery and private-source handling

Resolve accessible account/org repository pages and paginate results. Record scope, inaccessible repositories and truncated trees. Search narrowly by relevant paths/functions; use pinned selective file retrieval before any large clone. The existing 51-entry accessible metadata inventory is a bounded observation, not a complete source audit.

Read code, manifests, licenses, tests and issue discussions for finalists. Private code, internal paths, secrets, datasets and business data remain outside public evidence. Publish only a safe decision summary unless disclosure/reuse rights have been established. Founder ownership of source does not establish third-party dependency or enterprise-license rights.
