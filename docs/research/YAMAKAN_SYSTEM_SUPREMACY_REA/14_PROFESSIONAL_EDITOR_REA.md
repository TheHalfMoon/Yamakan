## System-level comparison and decisions

### Persistence, undo and recovery

A project file, a media archive, an autosave and a durable transaction solve different problems. Premiere project locking prevents conflicting writers at a file/project boundary; Final Cut distinguishes library database backups from media; VEED preserves the current version during restore; Riverside exposes saving before export. None demonstrates that Yamakan should abandon its verified SQLite transaction, request receipt or restore-fencing contracts.

**Decision:** preserve `Store.applyOperations`, revision/CAS, immutable assets/documents and restore-to-new-root. Show saved revision, export revision and recovery choices consistently. SS-015 must prove full media/document closure, including fonts/LUTs/unsupported effects where relevant, and report losses before conversion. Existing YU-014 and YU-025 are retained, not reimplemented.

### Preview and rendering

Resolve, Filmora, PowerDirector and Shotcut distinguish source media from editing derivatives. After Effects separates cache and per-frame memory constraints. These sources support separating decode, scale, composition and encode costs; they do not support a promised M-profile speedup.

**Decision:** retain owned FFmpeg reference export and proxy playback. SS-005a measures the existing graph; SS-005b may optimize only demonstrated redundant work. SS-009/010 target stale cache results, buffer lifetime, A/V clock and long-session measurements. No GPU or concurrency increase is selected.

### Timeline precision and effects

VEED documents frame stepping; Kapwing provides explicit ripple/keyboard actions; Canva's guide states transition-track restrictions. Proprietary implementation timing and rational arithmetic remain UNKNOWN. The inspected Yamakan `core/takes.ts::TakeProposalSchema` already binds the exact clip mapping, revision, story content and media versions; `yamakan.take.apply` recomputes it inside canonical operations. A new generic proposal engine is not justified just to reproduce this behavior.

**Decision:** SS-011 wraps existing compare/propose/apply commands in UI. SS-014's first scope is precise keyboard/drag interaction over existing trim/split/crossfade/keyframe commands, with rational-time and locked-track tests. Multicam, arbitrary compositing graphs, HDR and advanced retiming remain DEFERRED; no claim of professional feature parity.

### Professional audio, captions and cohesive UX

The product studies favor distinct but connected edit, source-management and finishing controls. Descript's source replacement versus local replacement is especially relevant to selective revision; CapCut's preview-quality warning shows why an export-quality label must not mislead.

**Decision:** SS-012 first exposes existing sound unlink/gain/fades/loudness through one undoable workflow; it does not build a mixer/DSP framework. SS-013 integrates existing cue editing with precise frame boundaries and mixed-script keyboard access. Native Arabic assessment remains H1. Story/Edit/Finish keep one project and revision; agent change review shows affected scope rather than internal execution machinery.

## Evidence limits and closure

All fifteen required names have a dated primary-source observation or an explicit unavailable/current-runtime decision. Closed-product database internals, worker ownership, API durability, deterministic replay, long-session performance, crash recovery correctness and matched benchmark superiority remain UNKNOWN unless independently demonstrated. Official feature descriptions are DOCUMENTED, not EXECUTION VERIFIED.

The product comparison resolves the architecture choices needed for these tasks: reuse current authoritative mechanisms, adapt explicit user-facing contracts, and defer unsupported replacements. Selected open-source function/license/dependency closure remains in R-03/R-04. This report still requires fresh independent review; it does not by itself mark R-01 VERIFIED or release the implementation hold.
