# R-04: accessible repositories and harness decisions

Research date: 2026-11-02. Authenticated `gh api user/repos --paginate --slurp` with `affiliation=owner,collaborator,organization_member` returned **58 accessible repositories: 20 public, 38 private**. Organization membership returned no entries; this does not exclude collaborator access. This supersedes the earlier 51-entry inventory. All 58 metadata entries were screened; promising repositories received pinned tree and selected implementation inspection. This is not a claim to have read every file in every repository, or to have accessed other accounts.

Private inventory, source bytes and retrieval hashes remain in the ignored local research archive. Public evidence contains no private paths or code. The private Flind recursive tree was truncated; its sampled licensing and checkpoint boundary were sufficient to reject transplanting that system, not to claim an exhaustive audit. No credentials, project datasets, customer records or model weights were read. No donor code or tests were executed.

## Private discovery disposition

Additional relevant private repositories were inspected beyond metadata: seven implementation samples cover evidence semantics, session handoff, checkpoint capture, step claims, local cancellation and store recovery; an additional automation-only tree was screened without selecting a runtime. Exact names, pins, file ranges and hashes remain local. These samples introduced no qualified new donor. The safe outcome is **REJECT private runtime transplantation** because the selected opportunities are already covered by Yamakan/public donors, or because they add incompatible stores/frameworks or unresolved component rights. This is a bounded reuse decision, not a security verdict on those repositories.

Flind, explicitly requested by the founder, was accessible privately. Its selected checkpoint/license sample adds Django/LangGraph/database and component-license closure; **REJECT transplant**. The truncated recursive inventory remains a disclosed limitation. A future opportunity in an uninspected subtree requires a new narrow qualification, not a claim that this pass certified the whole repository.

## Integration contract shared by selected conceptual adaptations

No production source is copied in this planning PR. New code must use current TypeScript/Node/SQLite, registry schemas, ProjectStore transactions, request receipts, execution epochs, managed artifacts and owned worker cancellation. The public pins above are research pins, not dependency upgrade requests. Existing imported pins/notices in `docs/provenance/imports.json` remain unchanged.

**Compatibility:** retain existing project format, writer-scoped history, old receipt readability and scoped agent mutation semantics. A planner context record grants no permission. **Security:** stale project/revision/epoch, altered input hash, unknown manifest, revoked consent, foreign project and uncertain external result fail closed. No private code, secret, absolute local path or raw provider response enters public evidence.

**Performance:** reuse current queue depths, process bounds and document budgets; no new service, memory store, background scheduler or network dependency. No source-based speedup is claimed. **Acceptance:** SS-006/007/008 must exercise unchanged-success controls, duplicate/out-of-order events, lost response, interrupted publication, lease loss, restart and cross-project refusal. A stopped process alone does not prove an external action failed.

**Rollback:** revert each adapter/UI/test delta independently; never delete audit history, synthesize successful receipts or replay uncertain actions. **Maintenance:** Opus assigns one owner for registry/store/Director changes; donor updates require a new pin/diff/license assessment. The root source analysis is complete at this bounded standard; independent architecture, correctness and security review are still required before R-04 becomes VERIFIED.
