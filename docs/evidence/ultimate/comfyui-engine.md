# Local ComfyUI engine adapter

Builder: Claude Opus, 2026-11-05. Founder authorization: see `docs/FOUNDER_DECISION_RECORD.md`. **No AI output was generated, and no model is enabled.** `ENGINE_ENABLED` stays `false`, no recipe is pinned, cloud providers stay off.

## What exists now

`core/engines/comfyui.ts` implements the existing `EngineAdapterV2`. It speaks only to `127.0.0.1` or `[::1]` by number, follows no redirect, and runs only graphs the server owns: a request names a recipe, hash and model manifest, and fills that recipe's bindings. While off, no call does IO. **A person cannot generate anything yet.** One read-only command, `yamakan.engines.comfyui`, reports whether the ComfyUI named by `YAMAKAN_COMFYUI_URL` answers, its version and device, and whether it was started safely. It starts, installs and runs nothing, does no IO when no address is configured, makes one local request while engines are off when one is, the only call that does, and reports `generationAvailable` apart, which is false: a healthy connection is not working generation.

## Real run

`npm run qualify:comfyui`, against ComfyUI v0.44.0 (`2c75dc1b379a59e0880619d029607af5169a62ef`) on CPU with Python 3.12, installed outside the repository, using core nodes and no weights. Each output is a solid colour built from `EmptyImage` or an uploaded still, so this qualifies the path, not any model.

| Step                   | Result                                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------------------------- |
| Setup check            | Every core node found; a missing node and a missing model are each named, and report `WEIGHTS_ABSENT` |
| 30 fps                 | Real H.264 MP4, 64×36, 30 frames, first frame `255,1,0`                                               |
| 24000/1001             | Real H.264 MP4, 64×36, 48 frames, first frame `255,1,0`                                               |
| Upload                 | A still reached `LoadImage` through ComfyUI's upload; MP4 with 30 frames, `1,0,253`                   |
| Input failing its hash | Not submitted                                                                                         |
| Cancel                 | A running job was interrupted, ended `cancelled`, and left no output                                  |

`tests/comfyui-engine.test.ts`, 40 tests against a fake server on a real port, also covers: addresses other than loopback, a redirect not followed, recipes with no qualification, a graph or URL in a request, outputs beyond a recipe's limits, stale generations, a path outside the output folder in history, temporary previews not counted, and real socket progress for only this execution.

**Added after review:** `comfyLaunchArguments` gives ComfyUI's arguments, on loopback with `--offline` and no custom nodes; nothing calls them outside the qualifier yet. `--offline` turns partner nodes off and restricts ComfyUI's browser page. **It is not an egress block on ComfyUI's process.** A recipe using a partner node reports `cloud-node` and is not available, judged by ComfyUI's flag or by the module the node came from, since a review found a partner node, `Krea2StyleReferenceNode`, that uploads images without setting the flag. The real run shows no such node with `--offline`, and as a control, finds them without it, including that one. Measured: 690 nodes with `--offline`; 1,035 without, of which 345 are partner nodes.

A submit whose answer is lost stays followed by its id and reports `unknown`, and the same generation replays it. **A new generation can still overlap it:** if `/prompt` times out, ComfyUI can enqueue the job afterwards, the cancel finds nothing, and both run until that job appears and is cancelled. A real timeout was not provoked; tests use an unreadable answer.

**Decided by the founder on 2026-11-05: a person starts ComfyUI, and Yamakan does not own its process.** Its worker sandbox allows no network and no GPU (`core/process/owner.ts`), and ComfyUI is a server that needs a loopback socket and, for a real model, a GPU, so owning it there would widen a security boundary. **This moves the exposure rather than removing it: a copy a person starts has no Yamakan sandbox at all**, no memory limit, and no process Yamakan can stop or confirm stopped. This departs from the earlier `docs/LOCAL_INFERENCE.md`, the job contract for model operations, `docs/IMPLEMENTATION_PLAN.md`'s isolated ComfyUI, and `docs/review/CLAUDE_INDEPENDENT_REVIEW.md`, which requires a Job Object before a local inference worker is enabled. The founder chose this knowing so. Generation is not enabled or wired; only the read-only health command reaches this.

So a person starts ComfyUI, and the adapter reads the arguments it reports, at each setup check and again at each submit since it may have been restarted. A copy without `--offline` and `--disable-all-custom-nodes`, with `--whitelist-custom-nodes`, `--enable-manager` or its legacy form, `--enable-agent`, `--enable-cors-header` or `--front-end-version`, or listening beyond loopback, is `not-started-locally` and not used. The check allows for `--flag=value`, shortened flags and a repeated `--listen`. It reads arguments only: an environment variable, or a model folder configured by `extra_model_paths.yaml`, would not show. A spelling it does not recognise, such as `--offl` or the deprecated `--disable-api-nodes`, is refused, which fails closed. **The reported arguments are ComfyUI's own word, not proof:** another program on that port could say anything.

Cancelling on a copy the person also uses is limited: ComfyUI checks and then interrupts, so an interrupt could land on the person's next job.

**The whole path, with no AI.** `npm run qualify:comfyui-generation` against real ComfyUI on CPU, core nodes, no weights, at 24000/1001: a generation starts on an explicit request, is followed to success, and its 48-frame output is imported as one asset with no clip added. It is then placed on the timeline and exported by the real pipeline, and every one of the export's 48 frames decodes green. **The source is a solid colour, so this shows nothing about any model.** A real model's prompt, an image-to-video in this path, and whether its output's frame rate is accepted were not exercised: `2997/125` was accepted here at 48 frames, and a refusal would need a conversion step this path lacks. It ran `core/engines/generation.ts` directly. `tests/generation-service.test.ts` covers refusals, importing before finishing, and output that differs from what was reported.

**The commands reach the service, and this build still refuses them.** `yamakan.generation.start`, `status`, `cancel` and `import` call it when a service exists, and tests inject one to prove that, and that an agent cannot start, cancel or import. No service is ever built here: engines are off and no recipe is pinned, so a person gets the reason. There is no browser control yet. A generation is held in memory, so a restart forgets it; progress over a real model run is not done. An import is refused once the generation was cancelled, unless the cancel arrives after the store has started taking it. The temporary copy can reach 4 GiB before the store's disk check.

**Consent and lineage.** A first frame a pack links to a person goes to the engine only if that person's newest linked consent is usable now for generating: revoked, expired, wrong-purpose, not revalidated after a restore, or missing all refuse. Placing existing media ignores expiry, by the founder's decision; making something new from a likeness does not. It is checked before submit, again as the file is about to be read, and at import before and after the download. An import returns lineage: output and input hashes, recipe, model manifest, seed and an unsalted prompt hash, so a guessable prompt can be confirmed by trying it.

**Limits:** these are checks at moments, so a revocation just after one still gets through, and a running generation is not stopped by a revocation. The still and output stay in ComfyUI's folders. Only the first frame is checked, since no other input exists. **A still of a person in no pack passes, and so does a re-encoded copy,** since the check goes by hash. A video imported before a revocation stays, and is not gated at placement unless a story's take carries its continuity references, which this service does not produce. Lineage is stored nowhere: a take can hold its output and inputs, not the rest. **Pinning a recipe would not yet make this run,** since nothing calls the adapter's setup check on this path. These ran against a contract double, not real ComfyUI.

**Found by the real run:**

- **Frame rate is not exact.** At 24000/1001, ComfyUI's `CreateVideo` wrote `2997/125`, not the rational asked for, because it takes a decimal. The frame count is right, but a generated clip's timing needs conforming on import. Not fixed here.
- **A rejected value was reported as missing weights.** Fixed: a value ComfyUI rejects is `INVALID_REQUEST` unless it is a missing node or a model file a recipe names. A copy started the wrong way is `ENGINE_DISABLED`. An unreachable ComfyUI, or a recipe not checked yet, also reports `WEIGHTS_ABSENT`, which is coarse.
- `EmptyImage` caps a batch at 4,096 frames, and 13 GiB of frames exceeded this host. Real recipes must declare limits they were measured at.

## This host cannot qualify a video model

Measured 2026-11-05: Intel UHD Graphics with no discrete GPU, 15.7 GiB RAM, 18.2 GiB free on C:, and 17.4 GiB on D:. `backlot` reports about 98 GB of required models and a 16 GB NVIDIA card for MiniMax H3, the heaviest stack surveyed; this was not measured here. **No video model has been downloaded, run or qualified here, and none is likely to run usefully on this host.** Qualifying one needs a machine with a suitable GPU, or a founder decision about which small CPU model is worth trying.

## For the founder to overrule or settle

- The brand rule bans the name ComfyUI as a donor product. Three files are excepted by exact path, and the health command's own sentence by exact wording, since these must name what they talk to; another user-visible use still fails.
- Cancelling a running job uses ComfyUI's targeted interrupt. ComfyUI checks between steps, so a long step may finish first, and `localProcessExited` is always false, since Yamakan does not own that process. Input files uploaded to ComfyUI are not deleted: its assets API can delete when enabled, which was not tried. An interrupt can arrive after ComfyUI's last check, so a cancelled job can still succeed; `remoteOutcome` stays `unknown` for this reason, and the service must fence publication.

## Not done

**Bounded since:** a job ComfyUI does not report fails after five minutes from when it was last seen, or from submission; one past its deadline is asked to stop, and fails. Lost means ComfyUI answered and does not know the job: an outage leaves it `unknown`, and a job that finished is not failed for aging out of its history. Either failure is final and leaves no output to read, and a job lost, or past its deadline with no acknowledged cancel, is cancelled if it appears within the next five minutes, as is a replaced job. An acknowledged cancel is not followed up: ComfyUI may answer yes and the job still run to its end, with its output unreadable here. These use a controlled clock against the fake server, and were not run against real ComfyUI. **Limits:** the deadline starts after uploads and the submit; it only acts when someone asks for status; laptop sleep could report a job lost; and after a restart or past 256 tracked jobs, a job has no bound and these cancels are gone. Automatic cancels add to the interrupt race above, so ComfyUI's atomic `POST /api/jobs/{id}/cancel` should replace `/interrupt`. **Required before this is wired to anything:** a decision on an allowlist of node classes. Pinned recipes may make that allowlist unnecessary, but a pinned recipe can only be trusted if each of its nodes was read, and whether other unflagged nodes reach the network by another route was not fully checked. A command or browser path to generate; a pinned recipe; any model; progress during a real model run; conforming a generated clip's frame rate; publishing an output as a project asset with consent and lineage; running on a GPU.
