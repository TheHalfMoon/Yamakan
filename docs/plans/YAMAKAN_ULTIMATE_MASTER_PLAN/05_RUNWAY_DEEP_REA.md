## Product conclusion and correction to stale comparisons

Runway combines its own models, third-party models, task-specific Recipes, Workflows, a preference-based Model Router, agent-assisted creative production and editing surfaces. Its competitive moat is the complete flow from references and creative intent to outputs and revisions, not just Gen-4.5 quality.

Do **not** repeat “Runway has no timeline” or treat its old unmaintained project editor as today's complete editing surface. The current [official Agent help](https://help.runwayml.com/hc/en-us/articles/51601639579667-Creating-with-Runway-Agent) documents assembling and editing cuts. Legacy Motion Tracking help says the old editor was retired **2026-07-30** with Timeline Studio/Edit Studio replacements. These were retrieved through free official-page web extraction because direct help-root HTTP returned403. They establish documented product behavior, not personally executed editing. The legacy export-failure article is historical evidence and cannot fairly characterize new Timeline Studio reliability.

Yamakan's opportunity is a durable local project with a serious editable timeline, predictable rendering, Arabic/English finishing and controllable provider cost. Runway already integrates many of these workflow concepts in cloud form. Winning requires measured editing/ownership/recovery advantages, not a claim that a generic agent + model picker is novel.

## Current model breadth and important limits

The [live catalog](https://dev.runwayml.com/models/catalog) includes proprietary Runway Gen-4.5,Gen-4 Turbo,Aleph2,Act-Two,Characters,Ruby and third-party video/image/audio models. Examples currently documented: Seedance2.5 up to30s480/720/1080 with image/video/audio refs; WAN3 2–30s with native audio; Kling3/O3 with variants720/1080/4K and multishot controls; MiniMax H3/H3 Max; Veo3.1; Gemini Omni Flash1.1; Grok Imagine1.5; GPT Image2.5,Seedream5,Nano Banana variants,Ideogram4.5,FIBO,Muse,Magnific and ElevenLabs. These are captured catalog claims; access varies by service/account/model. The SDK is transport code, never ownership of those model weights.

Current docs explicitly retire `gen3a_turbo` and `gen4_aleph`. Versioned adapter schemas are necessary; a UI retaining old model IDs will fail. Per-model ratio/duration/audio/reference requirements differ even on the same endpoint. Do not normalize to a lossy universal `{prompt,resolution,duration}` structure. Preserve required fields and unsupported intent as explicit validation errors.

Seedance2.5 draft mode is a useful cost-control pattern: 480p preview first, then `draftTaskId` enhancement to1080p within7days on the same account. The second request may contain only model and draftTaskId, reuses prompt/references/seed/audio and is separately charged. Draft is not free, enhancement is not a promise of identical pixels, and queue time/quality still require measurement.

## Provider lifecycle: critical implementation contracts

The context guide specifies asynchronous submit→id→poll→SUCCEEDED output or terminal failure; THROTTLED is a queue state, not retryable generation failure. Required header `X-Runway-Version:2024-11-06`. Ephemeral upload supports local files without public hosting. [Output docs](https://docs.dev.runwayml.com/assets/outputs.md) say returned URLs expire24–48h after access; fetch then persist to owned CAS, never retain only provider URLs.

Pinned `src/resources/tasks.ts` is more precise than a generic “cancel” button: refund is based on server-observed task status; RUNNING cancellation does not refund; a successful cancellation/refund does not guarantee generation stops; deleting completed task does not refund and may remove outputs. Model local cancellation intent, provider cancellation outcome, output availability and reconciled charge separately. Do not delete a completed remote task as a side effect of stopping local polling.

Moderation may be a terminal FAILED task rather than HTTP error, and official context says moderated generations are charged. This **differs from Higgsfield's published refund policy**. Terminal SDK task types expose actual `cost.credits`, pending types `estimatedCost.credits`; reconcile actual charge including partial/prepaid returns. API retry-on-timeout is not by itself proof of idempotent charged submission. No universal provider-side idempotency guarantee was established in this pass; future adapter must verify exact endpoint guarantees and fail into reconciliation when acceptance is ambiguous.

## What to emulate, improve, reject and still verify

Emulate explicit multi-model schemas, reusable references/Recipes, low-cost drafts, model-selection preferences, agent-to-edit workflow and useful professional formats. Improve project ownership, offline editing/recovery, byte-accurate revision exports, provider portability, transparent effective spend and tested Arabic typography/audio. Reject a second scheduler/project model, hidden model switches during approved generation, arbitrary plugin execution and using an SDK's migration CLI as proof of agent generation parity.

Remaining **UNKNOWN/blockers**: actual account/region access; output quality/adherence/latency and effective cost measured on common briefs; modern Timeline Studio professional depth and failure behavior; model router's quality-ranking implementation; private model source; hosted retention/training use beyond explicitly retrieved output docs; collaboration permissions/export/interchange; Arabic native speech and full UI correctness; exact per-endpoint charged-submit idempotency. These limit parity and superiority claims. Public source research is complete enough to specify a narrow adapter and a fair benchmark; it does not qualify the service or authorize release.
