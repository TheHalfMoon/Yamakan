# Cuty AI: deep research, extraction and adaptation assessment

Research date: **2026-10-23, Asia/Riyadh**. Dedicated Cuty report requested as `CUTY_REA_REPORT.md`; this numbered document is its canonical equivalent in this package. Public-page capture and static distribution inspection only. No sign-in, generation, credits, paid research tools, installation or first-hand product test. Evidence: [competitor-cuty.json](evidence/competitor-cuty.json), including exact URLs, HTTP status, UTC capture time, SHA-256, short excerpts, package integrity and file hashes. Fetch date is not publication date; Cuty page publication/build version is **UNKNOWN**. CLI distribution version is **0.2.1**, Node requirement **>=22.12**.

## Decision

Copy Cuty's conceptual simplicity: start with a creative task, attach references, choose an eligible model, inspect cost, generate, keep and reuse the result. Improve this with an editable Yamakan timeline and local ownership. Cuty is a useful comparator for **multi-model orchestration and reliable agent task recovery**; evidence does not establish Cuty-trained video models, professional NLE depth, superior quality, or any locally runnable Cuty generation engine.

The supplied [Cuty Runway page](https://www.cuty.ai/product/runway-ai) is **a Cuty marketing/comparison surface**. Its fetched composer showed **Seedance 2.0** and said to use “similar features on Cuty AI.” It does not prove that Runway's models are available through Cuty. Runway findings belong in [05](05_RUNWAY_DEEP_REA.md).

## Evidence and UX boundaries

**OFFICIAL DOCUMENTATION:** public HTML renders navigation, forms, options, claims and published commercial terms. **SOURCE INSPECTED:** official npm package's distributed JavaScript, without execution. **ENGINEERING INFERENCE:** architecture and proposed acceptance below. **EXECUTION VERIFIED:** none. **COMMUNITY REPORTED:** not relied upon. **UNKNOWN:** runtime quality, latency, prompt adherence, paid account access and backend implementation.

The [home page](https://www.cuty.ai/) groups AI Video, AI Image, AI Avatar, AI Music, Character Swap and Agent CLI; tools are also grouped by media/task, with model-specific video pages. English and Arabic appear in the locale menu, alongside other locales. This establishes a locale selector, **not** Arabic speech accuracy, right-to-left editor correctness or translated support quality. Sign-in/sign-up precede authenticated generation; onboarding completion time and post-login navigation remain untested. Prompt galleries and creative examples support discovery; no full editable template format was retrieved.

Some routing evidence is actively cautionary: `/studio/ai-tools/motion-control` and `/character-swap` returned a generic tools catalog; `/studio/motion-control` and `/studio/character-swap` returned an image composer despite their titles. These HTTP 200 responses do **not** prove a working motion-transfer form. The manifest preserves them rather than silently treating status 200 as capability proof.

## Source-level Cuty CLI assessment

Static download, no install or code execution: [official tarball](https://registry.npmjs.org/@cuty-ai/cli/-/cli-0.2.1.tgz), **38 files**, unpacked metadata ~165KB; exact package and every file SHA are in evidence. Registry `dist.integrity` was captured and compared with the tarball SHA-512 during evidence inspection. No upstream Git commit or public implementation repository was identified: **pin is npm version plus cryptographic tarball/file hashes, not a fabricated Git SHA**. `package.json` declares **UNLICENSED**. No Cuty source is transplanted by this plan; any actual copy must be covered by an applicable recorded grant. That limitation does not block clean conceptual design or authorized source work elsewhere.

Dependency closure: Node built-ins in inspected distribution; no local model, GPU, Docker or database engine was included. GPU compute and production storage are hosted and **UNKNOWN**. Network/account/credits are mandatory for generation; offline `--dry-run` validates cached schemas only. Tests referenced by package scripts are not shipped in the tarball; test presence is **not** evidence of passing tests. Mature-looking request discipline does not establish defect-free implementation; no adversarial security/runtime qualification performed. Rollback is disable a future route while retaining imported media, lineage and receipts. Do not uninstall another app, mutate its account or discard remote task evidence during rollback.

## What to copy, improve and reject

**Copy conceptually:** task-first entry, model schema discovery, role-labelled media, cost caps, idempotent recovery, bounded waits and useful agent exit states. **Improve:** one local project from references to cut; visible differences between generation draft, chosen take and timeline edit; offline archives and cross-project asset reuse; genuinely tested Arabic UX. **Reject:** separate Cuty-style mini-app databases, ambiguous replacement of unsupported options, model-count competition, implying marketing comparisons prove provider access, and claiming neural enhancement from resizing alone.

The useful quality target is “fewer steps and lower cost to an accepted editable sequence,” not matching every menu item. Generation latency, adherence, visual quality, full export behavior, exact per-model credit schedules, template internals, collaboration and authenticated capabilities remain **UNKNOWN** until separately authorized tests produce receipts. This report closes public-source reconnaissance; it does not close those execution blockers.
