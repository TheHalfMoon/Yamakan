# Differentiation and capability decisions

Each capability has exactly one primary approach. 'BUILD' can mean extending existing Yamakan code; it does not imply rewriting working infrastructure. P0/P1/P2 are priorities, not claims of implementation. Donor inspections/pins in08 govern all copying. Selection is conditional on actual module closure and rights; a donor name alone never authorizes importing its entire application.

## Differentiation hypotheses to test

1. **A finished project remains yours:** complete offline media/document/receipt recovery, explicit interchange loss report and original-preserving takes. This must first be implemented across creative workspaces.
2. **Revise one shot without losing the edit:** model-independent takes and references bind to canonical shot/timeline state. Measure revision time, unintended changes and repeat costs.
3. **Bilingual finishing with professional precision:** Arabic/English captions, keyboard workflow and predictable rendering. Automated RTL is insufficient; native human review remains necessary.
4. **An agent you can supervise and resume:** exact proposals, real artifact verification, durable attempts and no surprise spend. Typed tools exist today; complete production still needs evaluation.

These are testable product advantages, not proof that Yamakan beats Higgsfield/Cuty/Runway. Model fidelity, camera adherence and soundtrack quality remain separate outcomes. A zero-inference-cost disabled feature is not a creative quality advantage.
